# 存档

[English](saves.md) | **简体中文**

## 存档位置

活动存档目录是项目内的 `work/save/`，不在应用包里。目录结构与游戏在主机上的存档数据相同（`slot_00/` … `slot_05/`、`option.sav`、相册、图鉴和 `storage/`）。

游戏挂载存档时，宿主会把它克隆为 `work/save.work/`。游戏每次提交时，完整的工作副本通过 APFS 克隆和目录交换发布回 `work/save/`，因此 `work/save/` 始终是完整、一致的快照。崩溃后残留的未提交工作副本会在下次挂载时丢弃。写入方持有排他锁 `work/save.lock`。实现位于 `host/filesystem.c`。

> [!WARNING]
> 游戏运行时对 `work/save/` 的修改**不会**被合并，会被游戏下一次提交覆盖。复制、导入或编辑存档前请先退出游戏，也不要让同步软件管理这个目录；请改用下面的内置 iCloud 同步。

## iCloud 同步

Mac 与 iPhone / iPad 可以通过 iCloud 云盘共享存档。不需要付费开发者账号：应用写入的是 iCloud 云盘中的普通文件夹。

- **Mac：** 开启 iCloud 云盘后，游戏会自动使用 `iCloud 云盘/Zelda-Mobile/`。macOS 可能会询问一次 iCloud 云盘的访问权限。`ZELDA_CLOUD_SAVE=off` 关闭同步；`ZELDA_CLOUD_SAVE=<文件夹>` 改用其他文件夹。
- **iPhone / iPad：** 首次启动时会要求选择文件夹。请选择（或新建）iCloud 云盘中同一个 `Zelda-Mobile` 文件夹。选 *Not Now* 下次启动会再问；选 *Don't Sync* 不再询问。`./script/ios.sh launch --cloud-setup` 可以重新出现这个询问。

工作方式（`host/cloud_save.m`）：

- `work/save/` 仍是正在使用的存档，上面的事务机制不变。同步只读取已发布的快照，只在游戏尚未挂载存档时替换它。
- 每台设备只发布自己的 `<设备>.zmsave`（整份存档打包成一个文件）和 `<设备>.json`（哈希、设备名称、时间以及它继承自哪些存档的历史），从不写入其他设备的文件，因此 iCloud 上每个文件只有一个写入方。
- 游戏存档 20 秒后、关闭窗口时以及 iOS 应用进入后台时会发布存档。
- 启动时、游戏读取存档之前，只有本机存档自上次同步后没有变化，其他设备较新的存档才会替换它。本机存档会先移到 `work/save-backups/<时间>-before-icloud`（保留最新 10 份）。
- 如果两台设备在上次同步后都玩过，游戏会询问要继续哪一份存档。另一份不会被删除：每台设备在采用其他设备的存档前，都会先备份自己的副本。
- 每个存档包在使用前都会核对 SHA-256 哈希，下载不完整的文件不会被读取。如果 30 秒后 iCloud 仍未送达存档，游戏会使用本机存档启动；冲突会在之后的启动时询问。

不要同时在两台设备上玩。同步无法跨设备加锁，下次启动时会要求你在两份存档中选择一份。

## 备份

退出游戏后复制整个目录，例如：

```sh
mkdir -p work/save-backups
cp -Rc work/save "work/save-backups/$(date +%Y%m%d-%H%M%S)"
```

`cp -c` 会建立 APFS 克隆，瞬间完成，在文件变化前不额外占用空间。

## 从主机导入存档

1. 用存档管理工具从你自己的主机导出《王国之泪》的存档数据。
2. 退出游戏，按上面的方法备份 `work/save/`。
3. 原始导出保持不动，例如放在 `local/save-imports/`（已被 Git 忽略）。
4. 用导出存档目录的副本替换 `work/save/` 的内容。

较早游戏版本的存档可以在 v1.4.3 中读取，游戏会自行升级。如果只替换某个 `progress.sav`，对应的说明文字和缩略图仍是旧的，存档列表可能显示错误的地名，直到游戏再次保存。

## iPhone / iPad

开启 iCloud 同步后，设备首次启动就会取得 Mac 的存档，不需要传输。未开启时，`./script/ios.sh transfer seed` 会把 Mac 上的存档复制到设备一次。之后设备保存独立的副本，不会回写 Mac。如果设备上已有内容不同的存档，传输会拒绝覆盖。
